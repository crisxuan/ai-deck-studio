# Layout Guide

The MVP layouts are intentionally constrained so agents can produce reliable decks.

## Layouts

- `cover`: title, subtitle, deck metadata.
- `agenda`: ordered list of sections.
- `section`: chapter break or major transition.
- `key-insight`: one dominant claim with supporting points.
- `two-column`: paired explanation or responsibility split.
- `comparison`: before/after, option A/B, or current/future contrast.
- `timeline`: staged roadmap or sequence.
- `metric-grid`: KPI summary.
- `code`: readable code or structured snippet.
- `closing`: takeaway, next steps, and contact.

## Repair Priority

1. Shorten content.
2. Move supporting context into `presenterNotes`.
3. Choose a better layout.
4. Adjust layout CSS only when realistic content still fails.
